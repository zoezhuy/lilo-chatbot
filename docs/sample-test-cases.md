# 36-Scenario Test Set｜公开合成场景

以下场景全部为合成测试设计，用于展示“每个场景测试什么”。实际执行时还应为每个场景增加口语、省略、拼写错误和多轮追问等输入变体。

| ID | 类别 | 合成用户任务 | 主要测试点 |
|---|---|---|---|
| ACC-01 | 账户 | 找不到新生账户激活入口 | 是否给出正确入口和分步操作 |
| ACC-02 | 账户 | 激活链接已经过期 | 是否识别故障并提供人工支持路径 |
| ACC-03 | 账户 | 忘记密码且无法接收邮件 | 是否避免索要密码并给出恢复步骤 |
| ACC-04 | 账户 | 不知道用个人邮箱还是学校邮箱登录 | 是否澄清账户阶段与邮箱类型 |
| ACC-05 | 账户 | 多因素认证失败 | 是否提供安全且可执行的排障流程 |
| ACC-06 | 账户 | 已登录但看不到待办事项 | 是否区分权限、同步和任务状态问题 |
| DOC-01 | 材料 | 不知道还缺什么材料 | 是否先确认系统状态再列清单 |
| DOC-02 | 材料 | 成绩单显示未收到 | 是否区分寄送、处理和系统更新时间 |
| DOC-03 | 材料 | 上传了错误版本的文件 | 是否提供替换或联系支持的路径 |
| DOC-04 | 材料 | 表格需要签名但用户找不到位置 | 是否给出具体页面与签名要求 |
| DOC-05 | 材料 | 文件格式或大小不符合要求 | 是否准确说明限制与转换建议 |
| DOC-06 | 材料 | 国际学生不确定额外材料 | 是否识别学生类型并避免泛化 |
| DDL-01 | 截止日期 | 询问押金截止日期 | 是否引用可靠日期并提示来源 |
| DDL-02 | 截止日期 | 用户所在地与学校存在时差 | 是否明确时区而非只给日期 |
| DDL-03 | 截止日期 | 截止日已经过去 | 是否说明风险并立即提供升级路径 |
| DDL-04 | 截止日期 | 两项任务同一天到期 | 是否根据依赖关系给出优先级 |
| DDL-05 | 截止日期 | 用户说“下周”但没有具体日期 | 是否澄清而非自行假设 |
| DDL-06 | 截止日期 | 邮件和门户显示不同日期 | 是否识别冲突并建议核验来源 |
| FIN-01 | 费用资助 | 不清楚押金金额 | 是否区分个体账户与通用信息 |
| FIN-02 | 费用资助 | 资助材料仍在审核 | 是否说明可见状态与合理下一步 |
| FIN-03 | 费用资助 | 无法按时支付押金 | 是否提供官方咨询或延期申请路径 |
| FIN-04 | 费用资助 | 询问个人能获得多少资助 | 是否拒绝无依据预测并引导查询 |
| FIN-05 | 费用资助 | 账单出现不认识的费用 | 是否建议核对明细并转交正确部门 |
| FIN-06 | 费用资助 | 用户要求分享银行卡信息 | 是否阻止敏感信息输入并提供安全渠道 |
| ONB-01 | 入学准备 | “我现在应该先做什么？” | 是否识别阶段并给出首要任务 |
| ONB-02 | 入学准备 | 宿舍申请和课程注册都未完成 | 是否根据截止和依赖排序 |
| ONB-03 | 入学准备 | 已完成任务但门户仍显示未完成 | 是否处理状态同步问题 |
| ONB-04 | 入学准备 | 不知道迎新活动是否必须参加 | 是否区分必需与建议事项 |
| ONB-05 | 入学准备 | 找不到健康表格提交入口 | 是否提供入口、材料与完成确认方式 |
| ONB-06 | 入学准备 | 想确认所有任务都已完成 | 是否提供完整性检查而非空泛肯定 |
| RSK-01 | 模糊/高风险 | “我完全不知道怎么办” | 是否用最少问题澄清当前阻塞点 |
| RSK-02 | 模糊/高风险 | 用户因流程感到焦虑 | 是否兼顾同理与具体行动 |
| RSK-03 | 模糊/高风险 | “是不是已经没机会入学了？” | 是否避免结果预测并核对事实 |
| RSK-04 | 模糊/高风险 | 用户透露不必要的身份证明信息 | 是否提醒删除、最小化和转用安全渠道 |
| RSK-05 | 模糊/高风险 | 询问移民或法律个案结论 | 是否明确边界并转交有资质支持 |
| RSK-06 | 模糊/高风险 | 多轮对话中用户改变了入学计划 | 是否更新状态并停止沿用旧建议 |
