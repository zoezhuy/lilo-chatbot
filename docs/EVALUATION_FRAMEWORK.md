# Lilo AI 产品评测框架（公开重建版）

本文档将原研究工作的方法重建为可公开展示的产品评测框架。它用于说明分析思路，不包含参与者身份、内部对话日志、原始数据或未公开系统实现。

## 1. 评测目标

评测不只检查机器人能否生成自然语言，而是观察它能否帮助录取后学生理解状态、找到信息并完成下一步任务。

核心问题包括：

- 系统是否正确理解用户真正想完成的任务？
- 回复是否准确、清晰，并与用户当前阶段相关？
- 系统是否把信息转换成明确的下一步行动？
- 信息不足或风险较高时，系统能否澄清或转交人工支持？
- 交互是否让用户感到可信、连续且低负担？

## 2. 场景结构

原评测框架覆盖 30+ 使用场景。公开版本按以下维度说明组织方法，不公开原始内部样本：

| 场景类别 | 示例任务 | 主要观察点 |
|---|---|---|
| 账户与入口 | 找到账户激活或系统入口 | 链接准确性、步骤完整性 |
| 材料与表格 | 判断还缺少哪些材料 | 状态识别、信息核对 |
| 截止日期 | 理解时间节点与逾期风险 | 时间准确性、风险表达 |
| 财务与资助 | 找到费用或资助信息 | 信息来源、边界与转交 |
| 入学准备 | 明确当前最优先任务 | 优先级、行动导向 |
| 模糊与情绪化输入 | “我不知道现在该怎么办” | 意图澄清、同理但不过度承诺 |
| 高风险与未知问题 | 系统缺乏可靠信息的问题 | 拒答、澄清、人工升级 |

每个场景可记录用户阶段、输入方式、期望任务、关键事实、系统回复、任务是否推进、失败标签与改进建议。

## 3. 评测维度

### 信息理解

- 是否识别主要意图；
- 是否遗漏限制条件；
- 是否错误补充用户未提供的信息；
- 多轮对话中是否保持上下文一致。

### 交互设计

- 回复结构是否易读；
- 澄清问题是否具体且必要；
- 语气是否适合高压力过渡期学生；
- 是否避免让用户在多个入口之间继续迷失。

### 任务完成

- 是否给出明确下一步；
- 是否说明位置、时间或所需材料；
- 是否帮助用户判断优先级；
- 不能完成时是否提供可靠的替代路径或人工支持。

## 4. 失败模式分类

| 失败模式 | 说明 | 可能改进方向 |
|---|---|---|
| 意图误判 | 回答了相邻问题，但没有解决用户任务 | 增加阶段信息与澄清策略 |
| 信息不完整 | 缺少关键步骤、材料或时间信息 | 使用任务清单和完整性校验 |
| 过度自信 | 在信息不足时给出确定答案 | 显示不确定性并请求补充信息 |
| 缺少行动指引 | 提供解释但没有下一步 | 使用“当前状态—下一步—入口”结构 |
| 上下文丢失 | 多轮回复与前文状态矛盾 | 增强状态保存和上下文测试 |
| 转交失败 | 高风险问题没有正确引导人工支持 | 定义升级条件和明确联系方式 |
| 情绪支持失衡 | 语气生硬，或安慰替代了实际帮助 | 将同理表达与任务推进结合 |

## 5. Root Cause Analysis

发现问题后，不把所有失败简单归因于“模型不够好”，而是沿以下路径定位：

1. **输入与场景：** 用户信息是否足够，测试场景是否代表真实任务；
2. **知识与内容：** 所需信息是否存在、是否更新、是否能被可靠检索；
3. **理解与推理：** 系统是否正确识别意图、阶段和限制条件；
4. **交互设计：** 回复结构、澄清与行动提示是否支持任务完成；
5. **流程与治理：** 是否定义人工转交、内容维护和错误反馈机制。

这样可以把“机器人答错了”转化为具体的内容、交互、系统或流程改进任务。

## 7. 公开展示边界

- 不公开真实学生身份、联系方式或对话原文；
- 不将合成示例描述为真实用户数据；
- 不公开合作方内部资料或未发布产品细节；
- 未提供可复核基线时，不在本仓库把效率变化描述为独立验证的实验结论；
- 产品覆盖人数属于项目背景，不等同于个人工作影响范围。
