# Findings & Recommendations（公开重建版）

以下内容是基于公开场景框架整理的产品假设与建议，不是对原始内部研究数据的复述，也不代表已经完成线上效果验证。

## 结构化发现

| 观察 | 产品含义 | 建议 | 如何验证 |
|---|---|---|---|
| 用户经常以“我该怎么办”开始，而不是使用标准任务名称 | 单次意图分类不足以支持真实求助 | 先识别学生阶段，再用一个具体问题缩小阻塞点 | RSK-01 与不同阶段输入变体的任务完成率 |
| 正确信息如果没有入口和下一步，仍不能推动任务完成 | 回复应服务行动，而不是只提供解释 | 采用“当前状态—下一步—入口—期限”回复结构 | ACT-01 占比与下一步识别正确率 |
| 日期、费用和个案状态具有高风险与高变化性 | 需要来源、更新时间和人工支持边界 | 显示来源与更新时间；冲突或个案问题自动升级 | KNO-01、UNC-01、ESC-01 的回归结果 |
| 同理表达可以降低压力，但不能替代任务支持 | 情绪体验与行动支持需要同时设计 | 简短确认情绪后给出一个最小可行动步骤 | RSK-02 的信任评分与任务推进评分 |
| “联系学校”过于宽泛 | 无效转交会把检索负担重新交给学生 | 明确部门、渠道、需准备的信息和合理等待时间 | ESC-02 发生率与转交完成率 |
| 多轮状态变化容易导致旧建议继续生效 | 学生阶段和任务状态应成为显式产品对象 | 保存已完成、待处理、阻塞和已变更状态 | CTX-01 与 RSK-06 回归测试 |

## 建议优先级

### P0：安全与可信度

- 对法律、移民、个人资助结果和账户安全问题建立明确升级规则；
- 防止索取或复述不必要的敏感信息；
- 对动态事实显示来源和更新时间；
- 信息不足时明确澄清或拒答。

### P1：任务完成

- 建立按学生阶段组织的任务状态；
- 使用“状态—动作—入口—期限”模板；
- 对材料、截止日期和多任务依赖做完整性校验；
- 让人工转交成为可完成的产品流程。

### P2：体验与持续优化

- 缩短高压力场景的首轮回复；
- 将同理表达与单一最小行动结合；
- 用失败代码和 RCA 责任归属建立版本回归看板；
- 分析用户推翻、重复提问和中断的原因。
